# VerveDeck 架构设计

## 1. 系统总览

VerveDeck 是一个容器化的大模型微调训练平台，覆盖 **数据 → 训练 → 评测 → 部署 → API 服务** 全链路，
单机（1 台 GPU 服务器）闭环，7 大功能模块：

| 模块 | 职责 | 主要组件 |
|---|---|---|
| 项目管理 | 租户/项目/成员/RBAC/审计 | Postgres（SQLAlchemy ORM） |
| 数据中心 | 数据集版本、解析、清洗、合成、标注 | rustfs（S3 主存储）+ MinerU + Argilla |
| 模型仓库 | 基座下载、LoRA/合并产物、血缘追踪 | HuggingFace Hub + DVC（本地元数据） |
| 训练中心 | CPT/SFT/DPO/合并，LoRA/Full/Freeze，DeepSpeed | LLaMA-Factory（任务容器） |
| 评测中心 | 规则匹配 / LLM-Judge / evalscope 榜单 | evalscope（任务容器） |
| 推理部署 | vLLM/SGLang 多副本、LoRA adapter 热加载 | vLLM/SGLang（任务容器） |
| 集群与监控 | GPU 心跳、排队调度、利用率、Dashboard | gpu-agent + 调度器线程 |

## 2. 关键设计

### 2.1 任务容器 = pause 占位 + docker exec

所有 GPU 任务（训练/评测/推理）**不**用 compose 静态编排，而是 backend 通过 Docker API 动态创建：

1. **创建占位容器**（`taskcontainer.create_container`）：
   - 镜像是真实任务镜像（如 `hiyouga/llamafactory:0.9.5`），但 `command=["sleep","infinity"]`，
     主进程只做"占位"；
   - **GPU 在创建时独占绑定**：`HostConfig.DeviceRequest(count=gpu_count, capabilities=["gpu"])`，
     nvidia-container-toolkit 把物理 GPU 注入容器，天然隔离；
   - 容器名规范：`ft-train-{job.id}` / `ft-eval-{task_id}` / `ft-infer-{dep.id}(-r{replica})`；
   - 挂载 `/data`（任务目录/数据集/模型全部落盘可见）。
2. **exec 拉起真实进程**（`start_task`）：backend 起一个守护线程执行
   `docker exec`（如 `llamafactory-cli train /data/jobs/1/config.yaml`），
   stdout 实时写 `run.log`，进程退出码记入 `RUNNERS` 注册表。
3. **调度器轮询收敛**：每 5s 读 `RUNNERS` 退出码 → 成功/失败 → 注册产物/收集结果 → `remove_container`。
4. **取消**：`pkill` 容器内训练进程 + 强制删容器；checkpoint 保留在 `/data/jobs/<id>/ckpt` 供断点续训。

好处：
- GPU 容量 = 容器创建时的硬约束，调度器只需做"准入排队"（free = 节点 GPU 数 − 在用）；
- backend 重启可自愈：调度器发现 running 任务但 exec 上下文丢失时，标记失败并提示"断点续训"（checkpoint 已保留）；
- 容器生命周期与任务 1:1，日志/配置/tensorboard 全部在宿主机 `/data/jobs/<id>/`，容器删除不丢数据。

### 2.2 调度器（backend 后台线程，5s tick）

| 步骤 | 逻辑 |
|---|---|
| GPU 心跳 | gpu-agent 容器每 5s 写 `/data/gpu/agent.csv`；`gpu_service.tick()` 读入 `GpuMetric`，>60s 无心跳判离线 |
| 状态收敛 | 训练/评测：读 exec 退出码 → succeeded/failed；推理：容器存活检查 + creating→running |
| 准入调度 | `free = node.gpu_count − (running 训练 gpu_count + running 部署 tp×replicas)`；按 `priority desc, id asc` 逐个准入 |
| 模型下载 | `pending_download` 资产在 backend 线程内 `snapshot_download`（不起容器），完成后置 `ready` |
| 指标 GC | 每小时清理 6h 前的 `GpuMetric` |

**GPU 单卡互斥**：同一物理 GPU 不会被两个任务容器同时绑定——因为 GPU 绑定发生在容器创建时（独占），
调度器的容量检查只是排队准入的"软账本"，硬隔离由 nvidia runtime 保证。

### 2.3 数据集 = 版本化 + 对象存储

- 本地仓：`/data/datasets/<project>/<name>/`，DVC 管版本元数据（本地 remote）；
- **主存储：rustfs（S3 兼容）**：每个版本 commit 后 `storage.put_dir` 全量同步上传桶
  `vervedeck-datasets`，key = 本地路径相对 `/data`；
- 读路径统一走 `dataset_service.ensure_version_local`：本地缓存命中直接用（训练 symlink / 清洗 / 合成 / 评测
  都需要本地路径），未命中自动 `ensure_local` 从 rustfs 下载；
- `S3_ENDPOINT` 为空时全部调用点**无感降级**为纯本地存储（开发/测试环境）；
- 删除数据集：先删本地目录 + DVC 元数据，再 `storage.delete_dir` 删 S3 前缀。

### 2.4 权限与审计

- JWT 认证；角色 `admin / project_admin / member / viewer`，项目级 RBAC；
- 全部写操作经中间件落 `AuditLog`（含 401/403 拒绝记录）；
- 护栏规则（GuardRule）：正则命中输入/输出即拦截，支持项目级/全局 scope。

## 3. 数据目录布局（宿主机 `/data`）

```
/data
├── models/hub/<name>/        # 基座模型（HF 下载）
├── datasets/<proj>/<name>/   # 数据集本地仓（rustfs 主存储的缓存）
│   └── versions/v<n>.jsonl
├── jobs/<job.id>/            # 训练任务：config.yaml / dataset_info.json / run.log / ckpt/ / runs/
├── evals/<task.id>/          # 评测任务：task.json / test.jsonl / run.log / result.json
├── uploads/                  # 上传文件（MinerU 解析）
├── gpu/agent.csv agent.ts    # GPU 心跳
├── argilla/ postgres/ redis/ opensearch/   # 各服务数据
└── dvc-remote/               # DVC 本地 remote
```
