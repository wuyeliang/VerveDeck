# 一键部署指南

## 1. 前置条件

| 项目 | 要求 |
|---|---|
| 操作系统 | Linux x86_64（Ubuntu 20.04+/Debian 11+ 验证） |
| Docker | ≥ 24.x + **docker compose v2 插件** |
| GPU 驱动 | NVIDIA 驱动（nvidia-smi 可用） |
| nvidia-container-toolkit | 已安装（容器使用 `capabilities: [gpu]`） |
| 磁盘 | 建议 ≥ 500GB（模型权重 + 数据集 + 镜像） |
| 网络 | 可访问 Docker Hub（或已配置国内 registry mirror）与 HuggingFace（默认走 hf-mirror） |

> 无 GPU 也能部署：平台 CPU 功能（管理/数据集/DVC/Argilla）正常，训练/推理/MinerU 不可用。

### 1.1 全新机器基础依赖（一次性）

Docker 24+ / compose v2 / NVIDIA 驱动 / nvidia-container-toolkit 未装时，逐条执行（Ubuntu 24.04 验证）：

```bash
cat > /root/setup.sh << 'SH'
set -x
export DEBIAN_FRONTEND=noninteractive
dpkg --configure -a || true
apt-get install -f -y
apt-get update -y
apt-get install -y curl ca-certificates gnupg build-essential dkms linux-headers-$(uname -r)
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" > /etc/apt/sources.list.d/docker.list
apt-get update -y
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
VER=$(apt-cache search -n 'nvidia-driver-5[0-9][0-9]' | awk '{print $1}' | sed 's/^nvidia-driver-//' | sort -n | tail -1)
apt-get install -y "nvidia-driver-$VER"
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -fsSL https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#' > /etc/apt/sources.list.d/nvidia-container-toolkit.list
apt-get update -y
apt-get install -y nvidia-container-toolkit
nvidia-ctk runtime configure --runtime=docker
systemctl enable --now docker
nvidia-smi
SH
bash /root/setup.sh
```

```bash
# 若 nvidia-smi 仍不可用（首次装驱动），执行 reboot 后再验证
nvidia-smi
```

> 仓库 `deploy/setup-a3.sh` 为依赖修复变体（假设 Docker apt 源已配置，适用于安装中断后修复续装），完整脚本以上面内嵌版本为准。

## 2. 获取代码

```bash
# 源码树结构（部署所需目录）
vervedeck/
├── deploy/                  # compose + 一键脚本 + .env.example
├── images/                  # 6 个镜像构建上下文
└── platform/
    ├── backend/             # FastAPI 后端
    └── frontend/            # React 前端
```

将 `vervedeck/` 拷贝到目标机（如 `/opt/vervedeck/`），然后：

```bash
cd /opt/vervedeck/deploy
sudo bash deploy.sh
```

`deploy.sh` 依次执行：

1. **环境预检**：docker / compose / nvidia-smi 检查（GPU 缺失仅告警）
2. **生成 .env**：首次从 `.env.example` 复制（含默认值）
3. **创建 /data 目录结构**
4. **构建任务镜像**（`build-images.sh`，幂等：已存在则跳过，`REBUILD=1` 强制重建）
5. **`docker compose up -d`** 拉起全栈
6. **健康等待**：轮询 backend `/health`（最长 120s），确认 rustfs 健康
7. 打印访问入口与默认账号

## 3. 服务栈一览（deploy/docker-compose.yaml）

| 服务 | 镜像 | 端口 | 说明 |
|---|---|---|---|
| web | fintune/web:1.0 | **3000**→80 | nginx：前端静态资源 + /api 反代 backend |
| backend | fintune/backend:1.0 | 3001（内网） | FastAPI 全模块 + 调度器；挂 `/data` + docker.sock |
| postgres | postgres:16-alpine | 内网 | 业务库 fintune/fintune |
| redis | redis:7-alpine | 内网 | Argilla 缓存 |
| opensearch | opensearch 2.17.1 | 内网 | Argilla 2.x 强制搜索引擎（单节点、关安全插件） |
| argilla | fintune/argilla:1.0 | 内网 3000 | 数据标注；启动自动建服务账号 |
| **rustfs** | rustfs/rustfs:latest | **9000** S3 / **9001** 控制台 | 对象存储：数据集版本主存储；命名卷 `rustfs-data` |
| mineru | fintune/mineru:1.0 | 内网 8000 | PDF/文档解析（占 1 GPU） |
| gpu-agent | nvidia/cuda base | — | 每 5s 写 `/data/gpu/agent.csv` 心跳 |

**任务镜像**（非 compose 服务，由 backend 动态创建容器使用）：
`fintune/llama-factory:1.0`、`fintune/vllm:1.0`、`fintune/sglang:1.0`、`fintune/evalscope:1.0`

依赖顺序：`postgres(healthy) → backend`；`rustfs(healthy) → backend`；`opensearch(healthy) → argilla`。

## 4. 环境变量（deploy/.env）

| 变量 | 默认 | 说明 |
|---|---|---|
| ADMIN_PASSWORD | admin123 | 平台初始 admin 密码 |
| JWT_SECRET | please-change-me… | **生产必改** |
| POSTGRES_PASSWORD | fintune123 | 数据库密码 |
| RUSTFS_ACCESS_KEY / RUSTFS_SECRET_KEY | rustfsadmin | 对象存储凭据 |
| **S3_ENDPOINT** | http://rustfs:9000 | **置空 `S3_ENDPOINT=` 即关闭对象存储、纯本地** |
| S3_BUCKET | vervedeck-datasets | 数据集桶名（bucket 由 backend 启动时自动创建，幂等） |
| HF_ENDPOINT | https://hf-mirror.com | 模型下载镜像，直连改 https://huggingface.co |
| ARGILLA_API_KEY | fintune-argilla-key | 标注服务 API key |

## 5. 对象存储（rustfs）

- 数据集版本（`data.jsonl`/`raw.md`）commit 后自动全量上传至 `vervedeck-datasets` 桶；
- 本地 `/data/datasets` 是处理缓存：训练 symlink、MinerU 解析、清洗/合成需要本地路径；
  本地未命中时自动从 rustfs 回源下载（`dataset_service.ensure_version_local`）；
- bucket 由 backend 启动时后台线程自动创建（rustfs 就绪前每 10s 重试），无需手动建桶；
- 管理：`http://<ip>:9001`（rustfsadmin/rustfsadmin），或 S3 工具：
  ```bash
  mc alias set vervedeck http://<ip>:9000 rustfsadmin rustfsadmin
  mc ls vervedeck/vervedeck-datasets
  ```
- 降级：S3_ENDPOINT 置空后全部读写走本地，功能完全可用（开发/测试模式）。

```bash
docker compose -f /opt/vervedeck/deploy/docker-compose.yaml ps

# 2) backend 健康
curl -s http://127.0.0.1:3000/api/../health 2>/dev/null || \
curl -s http://localhost:3000/health   # 经 web 反代（若 nginx 未暴露 /health 则用容器内：
# docker compose exec backend curl -sf http://127.0.0.1:3001/health

# 3) 对象存储
curl -s http://127.0.0.1:9000/health
docker compose exec backend python -c "from app.services import storage; print(storage.health())"

# 4) 登录
# 浏览器打开 http://<ip>:3000，admin / admin123
```

## 7. 常用运维命令

```bash
cd /opt/vervedeck/deploy
docker compose ps                      # 状态
docker compose logs -f backend         # 后端日志（含调度器）
docker compose restart backend         # 重启后端（调度器自愈：running 任务标记失败提示续训）
docker compose pull rustfs && docker compose up -d rustfs   # 升级 rustfs
REBUILD=1 bash build-images.sh         # 重建全部任务镜像
docker compose down                    # 停栈（数据卷保留；/data 与 named volume 不删）
```
