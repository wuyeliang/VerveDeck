## 1. 产品定位

VerveDeck 是面向单机房/多机 GPU 集群的**开源一站式 LLM 工程平台**，覆盖"数据 → 训练 → 评测 → 压缩 → 部署 → 运维"完整闭环，以 OpenAI 兼容 API 对外提供服务。

设计目标：

1. **单机即可用**：一台 GPU 服务器 + 一条部署命令即可跑通全流程；
2. **多机可扩展**：节点注册制扩展，训练支持 torchrun 多机多卡（DDP/DeepSpeed/FSDP），推理支持多副本负载均衡；
3. **全开源引擎**：推理 vLLM/SGLang，训练 LLaMA-Factory，监控 DCGM + Prometheus + Grafana，对象存储 S3 兼容（内置 rustfs，兼容 MinIO 等）；
4. **私有化可控**：全栈容器化，数据不出机房，RBAC + 审计 + 护栏满足企业合规。

## 3. 核心机制

### 3.1 任务容器与 pause 现场保留

训练/量化任务以独立容器运行（"pause 任务容器机制"）：

- **取消 ≠ 杀死**：取消操作将容器 `docker pause`，进程冻结、GPU 显存与磁盘现场完整保留；
- **恢复即续跑**：`docker unpause` + 训练框架断点（checkpoint）继续，无需重新排队等资源的"冷启动"语义由平台队列兜底；
- **删除才销毁**：删除任务时清理容器，且**产物保护**——已注册进模型仓库的产物（合并模型/量化产物）不会被任务删除连带清除。

该机制使长训练任务的"暂停-观察-恢复"成为一等公民操作，而不是一次性的销毁式取消。

### 3.2 引擎镜像懒加载

平台不在部署/启动阶段预拉取引擎镜像（vLLM 单镜像 35GB+）：

1. 创建任务/部署时检测本地镜像；
2. 缺失则后台拉取（官方镜像 `docker pull`；自构镜像以宿主只读挂载的 `/repo` 源码树为上下文流式 `docker build`）；
3. 调度器每轮轮询镜像状态，ready 后才创建容器；
4. 镜像页展示拉取/构建进度，支持手动强制刷新。

效果：平台安装轻量（秒级），引擎按需付费（时间/带宽），且镜像版本可被集群升级机制热替换（运行时 pin 覆盖）。

### 3.3 模型血缘（Lineage）

所有模型资产（基座/LoRA/合并产物/量化产物）挂在全局血缘图上：

- 训练完成：LoRA 自动入库，`parent` 指向基座；
- 合并/量化完成：产物入库，`parent` 指向来源资产，命名规范（`quant-4bit-*` 等）；
- 血缘 API 返回完整链，前端可视化；
- 删除保护沿血缘生效（被引用资产不可删，量化产物即使任务删除也保留）。

### 3.4 LoRA 热加载

推理部署支持不停机挂/卸 LoRA 适配器（vLLM `/v1/load_lora_adapter` 语义）：

- 挂多个 LoRA = 一个基座服务多个微调，显存复用；
- 卸载需确认（指向该适配器的请求立即失败）；
- 与 OpenAI 代理打通：请求 `model` 字段指定适配器名。

### 3.5 多机多卡分布式训练

- 节点注册制：每台机器一个 gpu-agent 心跳上报（GPU 列表、驱动、CUDA、宿主指标），后端维护 `gpu_nodes`；
- 任务声明"节点数 × 每节点卡数"，调度器跨节点分配；
- 容器网络内 torchrun 拉起多进程，支持原生 DDP / DeepSpeed ZeRO / FSDP；
- IB/RDMA 环境下 NCCL 参数可配（NCCL_IB_* 等经任务高级参数透传）；
- RDMA 设备自动注入：创建容器时自动注入宿主 `/dev/infiniband`（uverbs*/rdma_cm）字符设备 + `ipc=host` + 宿主 libibverbs 只读挂载，NCCL 自动发现 HCA 走 IB 通信；无 IB 网卡的机器零影响。一键部署脚本检测到 IB HCA 时自动安装 rdma-core 用户态。

### 3.6 OpenAI 兼容代理与护栏

`/v1/{deploy_name}/*` 统一入口：

- **鉴权**：项目 API Key（Bearer），Key 可限定可访问模型集合；
- **转发**：按部署 `served_model_name` 映射归一请求体 model，透传流式 SSE；
- **护栏**：输入/输出经护栏规则（正则/关键词，可作用域到项目）拦截，命中返回 451；
- **可观测**：所有调用进审计日志（401/403 拒绝也记录）。

### 3.7 监控告警体系

三层采集：

1. **节点层**：gpu-agent 心跳（节点在线性/驱动/CUDA/宿主指标）+ node-exporter（CPU/内存/磁盘/网络）+ dcgm-exporter（GPU 利用率/显存/温度/功耗/ECC/Xid/降频/Remap）；
2. **工作负载层**：vLLM/SGLang/LLaMA-Factory 自带 `/metrics` 由 Prometheus 直采（推理 QPS/时延/KV 缓存，训练 loss/eval）；
3. **告警层**：平台管理 Prometheus 告警规则（DB 化、界面 CRUD、试算），Alertmanager 路由到企业微信/邮件（通道 DB 化可配）。

Grafana 以 iframe 嵌入平台监控大屏（`GF_SECURITY_ALLOW_EMBEDDING=true` + `GF_SERVER_ROOT_URL` 子路径，匿名 Viewer 只读），时间范围与仪表盘选择器由平台控制。

### 3.8 集群升级（蓝绿）

- **引擎类**（vllm/sglang/llamafactory/gpu-agent）：Docker Hub 版本探测（10min 缓存）→ pull 新 tag → 写运行时 pin（`/data/upgrade/image_pins.json`）；**运行中任务不受影响**，新任务使用新镜像；
- **平台类**（backend/web）：以宿主 `/repo` 重建镜像 + 蓝绿重建容器（临时名新容器 → 验证 running → 停旧删旧改名，服务别名保 DNS 不断）；
- **自升级收敛**：backend 自升级时旧进程随容器消亡，新进程调度器每轮 `converge()` 检查临时容器状态兜底完成切换（15min 超时判失败）。

### 3.9 安全模型

- **RBAC 四级**：super_admin / tenant_admin / developer / viewer，租户-项目两级隔离；
- **认证**：JWT（默认 72h）+ 首次登录强制改密 + 失败锁定（阈值/时长可配）+ IP 白名单；
- **审计**：全写操作 + 401/403 拒绝留痕，支持动作/用户/状态过滤检索；
- **传输**：443 强制 HTTPS（web 层 TLS 终结）；
- **内容安全**：护栏规则对推理输入/输出拦截；
- **密钥**：API Key 按项目签发、可限定模型、可批量吊销。

## 4. 数据目录与持久化

| 目录 | 内容 |
|---|---|
| /data/tenants、/data/projects | 租户/项目工作目录 |
| /data/models | 模型资产文件 |
| /data/datasets | 数据集文件（DVC 仓） |
| /data/upgrade | 运行时镜像 pin |
| /data/monitor | Prometheus/Alertmanager 状态 |
| rustfs 桶 | 对象存储数据（S3） |
| postgres 卷 | 全部元数据 |

备份 = postgres 逻辑备份 + /data + rustfs 桶，三者即全部状态。

## 5. 部署形态

| 形态 | 说明 |
|---|---|
| 单机单卡 | 最小形态，一条 `deploy.sh` 拉起全栈（约 10 容器） |
| 单机多卡 | 同机多 GPU，任务按卡分配；推理多副本 |
| 多机 | 每机部署 gpu-agent + 任务容器池，注册进集群；训练跨机 torchrun |
| 对象存储外置 | rustfs 替换为 MinIO/COS/OSS 等任意 S3（存储管理页配置后端） |

引擎版本全部可经「系统管理 → 集群升级」在线变更，无需重装平台。

## 6. 技术选型理由（摘要）

| 选型 | 理由 |
|---|---|
| FastAPI + SQLAlchemy + PostgreSQL | 异步 API、类型化、企业级元数据 |
| React + Ant Design | 组件密度与表格/表单能力，6 语言 i18n |
| Docker 原生编排（非 K8s） | 单机私有化场景下 K8s 运维成本过高；容器即任务，pause 语义直接 |
| DVC + Argilla | 数据集版本化与标注的成熟开源方案，避免自研 |
| Prometheus 全家桶 | 事实标准的指标栈，与 vLLM/DCGM 生态原生对接 |
| 镜像懒加载 + 运行时 pin | 平台轻量安装与引擎热升级两个诉求的统一解 |

## 7. 路线图方向
