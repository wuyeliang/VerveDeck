# 用户手册

VerveDeck 平台使用手册（面向平台使用者：算法工程师、运维管理员）。按左侧菜单顺序组织，覆盖从登录到模型上线的完整工作流。

> 英文版本：[en/09-user-guide.md](en/09-user-guide.md)

## 0. 登录与账户

- 浏览器访问 `https://<服务器IP>`（443，自签证书需点击"继续访问"）
- 默认管理员账户 `admin`，首次登录**强制修改密码**
- 右上角头像菜单：修改密码 / 退出登录
- 安全机制：失败多次自动锁定（阈值与时长由管理员在「系统管理 → 登录安全」配置）；支持 IP 白名单

## 1. 工作台（Dashboard）

首页汇总：GPU 利用率、运行中任务（训练/推理）、队列长度、最近告警、模型/数据集资产数。点击卡片跳转对应模块。

## 2. 数据中心（数据集）

**创建数据集**
1. 点击「新建」，填写名称/描述
2. 选择来源：本地上传（支持断点续传）/ 对象存储导入 / 文件解析（PDF、Office 经 MinerU 解析为文本）
3. 版本化：每次上传/提交生成新版本（DVC 管理），可查看版本历史、抽样预览、DVC 操作日志

**数据加工**
- 「解析」：PDF/Office → 结构化文本
- 「清洗」：批量清洗任务（去重/过滤/格式规范）
- 「合成」：数据合成任务（扩样本）
- 「标注」：接入 Argilla 标注界面

**删除**：行尾删除按钮（带确认）；勾选多行后点「批量删除」（带确认，被训练/评测引用的条目会报失败原因，不影响其余）。

## 3. 模型仓库

**获取模型（4 种方式）**
1. **HF / ModelScope 搜索下载**：搜索 → 选择 → 后台下载（断点续传）
2. **本地上传**：multipart 上传，大文件断点续传
3. **登记基座**：指向宿主机已有模型路径
4. **平台产出**：训练合并产物、量化产物自动入库

**血缘追踪**：资产详情 →「血缘」查看完整链路（基座 → LoRA 训练 → 合并/量化产物），每个产物可回溯到来源模型与训练任务。

**分类管理**：资产按分类平铺展示，支持搜索与分类筛选；修改分类/说明在详情中操作。

## 4. 训练中心

**新建训练任务（向导式）**
1. 选择基座模型（必须已就绪）
2. 选择数据集（自动校验必填项）
3. 配置参数：94 项参数分 10 组（对齐 LLaMA-Factory），常用组：
   - 基础：方法（SFT/DPO/PPO/KTO）、模板、LoRA rank/alpha
   - 数据：epochs、batch size、序列长度、打包
   - 分布式：**节点数 × 每节点卡数 = 总卡数**（多机多卡走容器网络 torchrun，支持 IB/RDMA）
   - 框架：原生 DDP / DeepSpeed ZeRO / FSDP
4. 提交后进入队列（GPU 不足时排队，可在「集群运维 → 计算节点」调优先级）

**任务操作**
- 「取消」：容器 pause 保留现场（带确认）
- 「恢复」：从 pause 现场继续训练
- 详情查看完整参数快照、训练曲线（loss/eval）、实时日志
- 训练完成：LoRA 产物自动入库并挂血缘；可合并为完整模型

## 5. 评测中心

- 创建评测：选模型（可对比基线）+ 评测集 + 方式（规则评分 / LLM 评审）
- 报告：得分明细 + 与基线对比，支持下载 Markdown
- 多任务对比：勾选多个评测任务并排比较
- 删除支持多选批量

## 6. 模型压缩（量化）

- 「新建量化」：选来源模型（已合并模型）+ 方式（GPTQ / AWQ / LLM.int8 / GPTQ-v2，界面显示各方式硬件要求）
- 产物自动注册进模型仓库（命名 `quant-Nb-*`），挂血缘，可直接用于推理部署
- 日志/状态实时可见；成功任务的产物受保护（删除任务不会误删已入库产物）

## 7. 推理部署（部署 / 路由 / 推理后端 / 缓存加速 四个子菜单）

### 7.1 部署

**新建部署**
1. 选模型（仓库中已就绪的资产）
2. 选引擎：vLLM（默认）/ SGLang；生效镜像由镜像 pin 系统（镜像管理页）决定
3. **推理配置**（可选）：
   - 推理后端：留空 = 内置引擎；选自定义后端（「推理后端」页注册）后可选版本（留空 = 默认版本）；自定义后端不支持 PD 分离
   - 缓存加速服务：关联后其推理实例注入 `VD_CACHE_ENDPOINT` 环境变量（服务未运行则优雅降级，不影响推理）
4. 部署拓扑（可选）：PD 分离（P/D 实例池 + NIXL/Mooncake KV 传输）、部署节点数、NCCL 环境变量
5. 运行参数：量化 / max_len / 显存占比 / 副本数 / 扩展 KV（vLLM CPU 卸载、SGLang HiCache）/ 附加 LoRA
6. 高级参数（可选，留空 = 引擎默认）：max_num_seqs、dtype、prefix_caching、chunked_prefill、served_model_name（对外暴露的模型名）、api_key（引擎级鉴权）、extra_args
7. 提交 → 后端先做 GPU 准入预检（GPU 不足直接 400 报需求/可用卡数）→ 容器启动 → 状态变 running

**日常操作**
- 启动 / 停止（带确认）/ 删除（运行中先停；支持多选批量删除）
- **编辑部署**：名称/描述/自动重启/后端选择即时生效；引擎/副本/运行参数/扩展 KV 变更自动停旧实例重建生效；PD 部署不可改协同 TP/副本（P/D 角色参数走扩缩容）
- **实例视角**（详情内）：单实例存活状态与 IP（协同副本 / PD P 池·D 池 / router）、单实例重建（删掉重造，部署级状态不变）；**错误自动重启**开关（指数退避 30s → 2h，人工启动清零退避；展示累计错误次数与下次重试时间）
- 副本扩缩容（需空闲 GPU）；PD 部署按 P/D 角色分别扩缩
- **LoRA 热加载**：详情内挂载 LoRA 适配器，不停机即时生效；热卸载前会提示（卸载后指向它的请求立即失败）
- 日志 / 指标（QPS、时延、KV 缓存，经 Prometheus）

**调用（OpenAI 兼容）**
```bash
# 在「租户与项目」里为项目创建 API Key
curl https://<ip>/v1/<部署名>/chat/completions \
  -H "Authorization: Bearer <API_KEY>" \
  -d '{"model":"<served_model_name或部署名>","messages":[{"role":"user","content":"你好"}]}'
```
- API Key 可限定只允许访问某些模型
- 命中护栏规则返回 451；部署未运行返回 503
- 支持流式（`"stream": true`，SSE）
- 同一模型可再建「路由」（见 7.2）获得加权分发与容灾能力，入口变为 `/v1/<路由名>/`

### 7.2 路由

- 路由数据面由 Higress 网关承载：**加权分发**（相对权重自动归一化到 100）+ **容灾接管**（主目标全不可用时容灾目标按比例接管，主目标恢复自动还原）+ 端点级重试（5xx/连接错误自动换端点）
- `/v1/<路由名>/` 前缀与部署名全局互斥（防止路径碰撞），创建时双向校验
- 目标管理：一条路由挂多个目标部署，每目标设权重 + 容灾标记；目标部署状态变化由调度器自动收敛
- 启用 / 停用：停用从网关摘除流量（目标保留，再启用即恢复）；所有变更下一同步周期生效，页面展示同步状态（待同步 / 已同步 / 同步失败 + 原因）
- 路由名即对外 API 前缀，不可修改（换名请删除重建）；被网关同步中的路由删除后由调度器自动清理网关残留

### 7.3 推理后端

- **builtin**（vllm / sglang）：系统种子、不可删；生效镜像跟随镜像 pin 系统（运行时升级自动反映），版本表展示基线版本与参数默认值
- **custom**（名称须以 `-custom` 结尾）：每个版本决定 镜像 + 启动命令模板
  - 占位符：`{{model_path}}` `{{port}}` `{{model_name}}` `{{worker_ip}}` `{{gpu_count}}` `{{gpu_ids}}` `{{变量名}}`（注入的环境变量）；未知占位符保留原样并告警，不静默吞掉
  - 健康检查路径：探活与指标采集（默认 `/v1/models`）
  - 默认环境变量 / 默认参数（JSON，供前端表单默认值）
- YAML 导入：仅创建不覆盖（名称已存在整批拒绝，错误逐条列出）
- 保护：被部署引用不可删；被部署引用的版本不可改版本号/删除；自定义后端不支持 PD 分离

### 7.4 缓存加速

两级加速：
1. **部署级扩展 KV**：vLLM `--cpu-offload-gb`（KV 缓存卸载到主存的 GB 数）/ SGLang `--hicache-size`（主机内存缓存层级 GB 数）；在部署创建/编辑表单或本页「部署级扩展 KV」区设置；变更会停止并重建部署实例，重建完成后生效
2. **缓存服务实例**（托管容器，如 KV 缓存存储）：
   - 启动命令留空 = 按镜像默认入口直跑；非空 = 容器内 `bash -lc` 执行（日志与退出码可查）
   - 生命周期：stopped → creating（等待镜像）→ running（健康收敛，IP 漂移自动刷新端点）；进程非零退出或端口抖动 3 连败 → failed（需人工重启）
   - 部署关联后向其推理实例注入 `VD_CACHE_ENDPOINT=http://ip:port`（服务未运行优雅降级为空）
   - 运行中修改配置自动重启；被部署引用不可删

## 8. 集群运维

**计算节点**
- 节点卡片：GPU 总数/在用/空闲、驱动、CUDA、宿主 CPU/内存/磁盘/网络、每卡利用率/显存/温度/功耗/时钟/ECC/Xid/降频/健康度
- 状态：在线/离线/维护中 + 状态说明（最后心跳时间 + 排障指引）；离线/恢复自动触发告警
- 维护模式：节点卡片扳手按钮「设为维护」（可填原因）——摘除服务：不判离线、不告警、GPU 不占调度容量；「结束维护」恢复
- 删除节点：卡片删除按钮，二次确认（删除同时撤销该节点全部注册令牌，防止节点端心跳进程"复活"重注册）
- 下方任务队列：调优先级（+1/-1/置顶）、运行中任务列表
- 多机扩展：super_admin 可添加/移除节点

**添加节点**（三步向导，参照 GPUStack Add Worker）
本机节点无需操作——gpu-agent 心跳自动纳管。远程节点：
1. **节点信息**：填节点名（如 `node-2`）+ 预期 GPU 数（可选，实际以节点端采集为准）
2. **环境检查**：给一段检查脚本（nvidia-smi/平台连通性），在目标机跑通 OK 后继续
3. **接入命令**：服务端签发 24h 有效、绑定节点名的注册令牌（`vdk-` 前缀），生成一键可复制命令；支持「撤销并重签」
   在目标机执行（先 scp 平台 `deploy/add-node.sh` 过去）：
   ```bash
   VD_PLATFORM=https://<平台IP>:8443 VD_TOKEN=vdk-xxxx bash add-node.sh
   ```
   脚本自动完成：环境检查 → 凭令牌注册（自动采集 GPU 卡数/卡名/驱动/CUDA/IB，节点名以令牌绑定为准，幂等）→ 启动**后台心跳守护**（每 10s 上报实时 GPU 快照；平台 90s 无心跳判离线并告警）。机器重启后重跑同一命令即恢复心跳。
   兼容旧方式：`VD_USER=admin VD_PASS=<密码> bash add-node.sh [节点名]`（账号登录，无令牌）。
   若新机器还要实际跑任务，需在该机再部署一套平台栈（`sudo bash install-from-iso.sh`），由 gpu-agent 心跳纳管；带 IB/RoCE 网卡时容器会自动注入 RDMA 设备（NCCL 多机训练走 IB）。

**GPU 设备**
- 全集群 GPU 明细表：显存进度条、温度、功耗与功耗限额、SM/显存时钟、ECC 错误、Xid、降频原因、Remap、健康度

**监控大屏**
- 时间范围切换（1h/6h/24h/7d）
- 引擎选择（Grafana 仪表盘，经平台 iframe 嵌入免登录只读）

**监控指标**
- 实时展示 Prometheus 中全部活跃监控指标目录：总活跃 series 数、指标类型数、按类别（宿主/推理/系统/其他）分布统计
- 指标表支持按名称搜索、按类别筛选、按 series 数排序；每行展示指标名称、类别、来源（node-exporter/DCGM/vLLM 等）、当前 series 数
- 30s 自动刷新，用于巡检"平台到底采了哪些指标、覆盖多少实例"（与 Grafana 大屏互补：大屏看趋势，此页看覆盖面）

**告警规则**
- 通知通道配置：企业微信（群机器人 Webhook）/邮件（SMTP），可发测试通知
- 阈值/事件规则：自定义分类（支持 5000 条容量，服务端分页 + 分类/类型/状态/名称筛选）、指标/事件类型、阈值、级别、冷却、生效通知通道
- 内置 39 条核心规则（对齐行业水位：覆盖全部 21 个可告警指标，warning/critical 两档 + 节点/任务/登录等事件型告警），首启自动补建，平台重启不会重复叠加
- 批量导入：CSV 每行一条规则

**告警事件**
- 告警事件流（10s 自动刷新）+ 过滤（级别/目标/确认状态）
- 单条与批量确认（ack，含确认人/时间）、取消确认、删除（带确认）

**日志中心**
- 选择容器服务查看实时日志（tail 行数可调）

**集群升级**（原系统管理迁入）
- 平台全量镜像清单（18 项，与镜像管理页完全一致）：各组件当前版本 / 可用版本（Docker Hub）/ 一键升级
- 升级方式：引擎类（vLLM/SGLang/LLaMA-Factory/evalscope）只更新运行时 pin（新任务生效）；自构类（MinerU/backend/web）以宿主源码树重建同 tag + 蓝绿重建容器；其余 11 个监控/基础设施组件（DCGM Exporter、Node Exporter、Prometheus、Alertmanager、Grafana 双实例、PostgreSQL、Redis、OpenSearch、Argilla、RustFS）拉新 tag + 蓝绿重建容器（影响提示见界面）

## 9. 租户与项目

- 租户 → 项目二级结构；项目是资源隔离与计费的基本单元
- 项目成员：添加/移除用户（移除带确认）、变更角色（带确认）
- 角色：super_admin（全局）/ tenant_admin（租户内管理）/ developer（用资源）/ viewer（只读）
- 项目 API Key：在此创建（OpenAI 代理鉴权用），可限定模型范围，支持批量删除

## 10. 存储管理

- 后端管理：添加 S3 兼容后端（endpoint/ak/sk/bucket）→ 连通性测试
- 对象浏览：目录式浏览、单对象删除（带确认）、**多选批量删除**（带确认；切换目录自动清空勾选）
- 平台数据集、模型文件均落在对象存储上，删除对象前先确认无平台引用

## 11. 镜像管理（super_admin）

- 平台全量镜像清单（18 项，与集群升级页同一数据源、顺序完全一致）：
  - 引擎（5）：vLLM / SGLang / LLaMA-Factory / GPU Agent / evalscope
  - 自构（3）：MinerU 文档解析 / 平台后端 / Web 前端
  - 监控与基础设施（10）：DCGM Exporter / Node Exporter / Prometheus / Alertmanager / Grafana（深色+浅色双容器）/ PostgreSQL / Redis / OpenSearch / Argilla / RustFS
- 每行展示镜像引用、来源（官方/自构）、本地状态、大小、版本（自动探测，首开显示"探测中…"后自动补全；无 shell 的镜像直接显示 tag，自构镜像显示构建信息）
- 操作：拉取（官方镜像）/ 重建（自构镜像，以宿主源码树 /repo 为上下文）/ 强制探测
- 自定义镜像：登记国产芯片等第三方镜像（name:tag 格式，追加在平台清单末尾），用于扩展部署选项

## 13. 通用交互约定

- **高危操作全部有确认**：删除/停止/取消/卸载/移除成员/角色变更/升级等均需二次确认
- **删除均支持多选**：各资源列表勾选多行 →「批量删除（N）」→ 确认 → 部分失败时提示失败原因，成功部分照常生效
- **国际化**：界面支持 简中/繁中/日/英/法/西，右上角切换
- **主题**：亮/暗主题切换（右上角）
