# 安全加固（公网部署）

VerveDeck 面向**单机自建 + 可能暴露公网**的部署形态设计。本文是安全加固总览：
内置防护矩阵、防暴力攻击链路、公网部署必做/建议清单。
（运维视角的日常命令与故障排查见 `07-运维手册.md`。）

## 1. 防护矩阵

| 层 | 机制 | 位置 |
|---|---|---|
| 网关（nginx） | HTTP 强制 301→HTTPS、TLS1.2/1.3、HSTS | `platform/frontend/nginx.conf` |
| 网关 | **限流**：登录 5r/s/IP、API 30r/s/IP、推理代理 60r/s/IP、单 IP 并发 50 连接，超限 429；**四项参数页面可配、保存即热生效**（系统管理→设置→网关限流，nginx reload 不中断连接，校验失败自动回滚） | `platform/frontend/zones.conf` + `app/services/gateway_service.py` |
| 网关 | 安全响应头：X-Content-Type-Options / X-Frame-Options / Referrer-Policy；隐藏 nginx 版本 | `nginx.conf` |
| 应用·登录 | **防暴力破解**：账号 5 次 / 单 IP 30 次失败 → 临时锁定 15 分钟（423）；阈值/时长/IP 白名单可在 UI 配置 | `app/api/auth.py`（系统管理→设置） |
| 应用·登录 | **锁定告警**：触发锁定时发 `login_locked` 事件（企微/邮件通道 + 告警事件页，cooldown 5 分钟去重） | `app/services/alert_service.py` |
| 应用·密码 | bcrypt 哈希；新建/重置/修改密码 ≥8 位；代设密码首登强制修改 | `app/api/admin.py`、`app/api/auth.py` |
| 应用·审计 | 全部写操作 + 全部 401/403 留痕（用户/**真实 IP**/路径/状态码/动作码），安全事件可筛选 | `app/audit.py`（系统管理→审计日志） |
| 应用·会话 | JWT HS256（72h 过期，密钥必须改）；API Key 192bit 随机、项目级、仅存 SHA-256 哈希 | `app/security.py` |
| 部署 | 端口暴露矩阵（§2）：仅 web 入口对外；3001/3002/3000/3003/9000/9001/9090 绑 127.0.0.1；9400/9100 默认本机、集群模式绑内网 IP；postgres/redis/opensearch/alertmanager/任务容器仅 fintune_net 内网；Docker API 不暴露 TCP | `deploy/docker-compose.yaml` |
| 部署 | 首启自动生成强随机密钥（.env 权限 600）；存量 .env 弱默认值检测告警 | `deploy/deploy.sh` |
| 内部接口 | Alertmanager webhook 回调需内部令牌（`X-Vervedeck-Token`） | `/api/internal/am-webhook` |

## 2. 端口暴露矩阵（公网 / 本机 / 内网）

策略：**仅 web 业务入口对外，其余端口一律绑 127.0.0.1 或内网（集群模式）**；
Docker API 不暴露 TCP（仅本地 socket）。已按 `ss -tlnp` 在公网服务器实测核对（2026-11-17）。

| 端口 | 服务 | 监听 | 说明 |
|---|---|---|---|
| 80 | web（nginx） | 公网 | 仅 301 → HTTPS |
| 443（或自定义端口，如 8433） | web（nginx） | 公网 | **唯一业务入口**：/api/、/v1/、/grafana(/-light)/、/argilla/ 全部经此同源代理 |
| 22 | sshd | 公网（建议限源 IP） | 运维通道；`ufw allow from <办公IP> to any port 22` |
| 3001 | backend（uvicorn） | 127.0.0.1 | web 经此转发 /api/ 与 /v1/ |
| 3002 | argilla | 127.0.0.1 | web 经此转发 /argilla/ |
| 3000 / 3003 | grafana / grafana-light | 127.0.0.1 | web 经此转发 /grafana/ 与 /grafana-light/ |
| 9000 / 9001 | rustfs S3 / 控制台 | 127.0.0.1 | 仅宿主机 mc/客户端 |
| 9090 | prometheus | 127.0.0.1 | 本机调试；UI 入口为 Grafana |
| 9400 / 9100 | dcgm-exporter / node-exporter | 127.0.0.1（默认）/ 内网 IP（集群模式） | `.env` 的 `SCRAPE_BIND_IP`：deploy.sh 首启写入内网 IP，集群模式下主节点 Prometheus 经内网 scrape 本节点 GPU/宿主指标 |
| 5432 / 6379 / 9200 / 9093 | postgres / redis / opensearch / alertmanager | 仅 fintune_net 内网 | 无宿主端口映射，容器间经容器名访问 |
| 8000 | mineru / 推理容器（vLLM·SGLang） | 仅 fintune_net 内网 | backend 经容器 IP 反代（外部访问走 443 的 /v1/）；指标由 prometheus 经容器 IP 直采 |
| 2375 / 2376 | Docker API | **不暴露** | 仅本地 /var/run/docker.sock 挂载进 backend |

**集群模式（多节点）跨节点流量**——全部走内网，不新增任何公网端口：

| 方向 | 端口 | 用途 |
|---|---|---|
| 节点 → 主节点 | 443/8433（主节点入口） | add-node.sh 节点注册（POST /api/cluster/nodes） |
| 主节点 → 节点 | 9400 / 9100（节点内网 IP） | 主节点 Prometheus scrape 节点 GPU/宿主指标（`SCRAPE_BIND_IP`） |
| 节点 ↔ 节点 | 容器网络（fintune_net 互通，L2 或 RDMA） | 多机 torchrun MASTER_PORT / NCCL 跨机训练 |

注意：
- 远程节点的指标要进主平台「集群运维」页，需把该节点内网 IP 加入**主节点**
  `deploy/monitoring/prometheus/prometheus.yml` 的 static targets 后热加载
  （`POST /-/reload`）；节点侧 9400/9100 已按 `SCRAPE_BIND_IP` 绑内网 IP，
  主节点可达、公网不可达（云安全组/防火墙不要开放这两个端口）。
- 单机部署无需任何操作：`SCRAPE_BIND_IP` 缺省时 exporter 只监听 127.0.0.1。
- 其他 0.0.0.0 监听（如 PCP 的 pmcd 44321 / pmlogger 4330，默认全接口监听）
  属宿主无关服务，deploy.sh 会停掉并禁用；新装的宿主服务若监听公网，按同一原则处理。

## 3. 防暴力攻击链路（以登录爆破为例）

```
攻击者 → 公网 443
  ① nginx limit_req：>5 次/秒 直接 429（攻击流量到不了应用层，bcrypt 不耗 CPU）
  ② backend 双维度锁定：
       - 单账号连续失败 5 次 → 该账号锁定 15 分钟
       - 单 IP 连续失败 30 次 → 该 IP 锁定 15 分钟（拦"单 IP 撞大量账号"横向爆破）
       - 可选 IP 白名单（办公出口 CIDR）：名单外直接 403
  ③ 锁定触发 → login_locked 告警（企微/邮件）+ 告警事件页可见
  ④ 审计日志：每次 401/423 留痕（真实 IP），事后可还原攻击源与尝试账号
```

各层参数均无需改代码即可调整：
- **nginx 限流阈值**：系统管理→设置→网关限流（四档：登录/API/推理代理速率 + 单 IP 并发）。
  保存后 backend 重新渲染 `00-zones.conf` → `nginx -t` 校验 → `nginx -s reload` 热加载
  （存量连接不中断；校验失败自动回滚原配置）。配置持久化于 DB，web 容器重建后
  backend 启动自愈会重新应用；部署文件 `deploy/nginx/00-zones.conf` 随保存同步落盘。
- **锁定阈值/白名单**：系统管理→设置（DB 配置，10s 生效）。

## 4. 公网部署必做清单

1. **防火墙最小放行**（ufw 示例）：
   ```bash
   ufw default deny incoming
   ufw allow from <办公出口IP> to any port 22 proto tcp   # SSH 限源
   ufw allow 80,443/tcp
   ufw enable
   ```
2. **改所有密钥**：`deploy/.env` 的 `ADMIN_PASSWORD` / `JWT_SECRET` / `POSTGRES_PASSWORD` /
   `RUSTFS_SECRET_KEY` / `ARGILLA_API_KEY` / `GRAFANA_PASSWORD`（deploy.sh 首启已自动生成随机值；
   手工部署的 `.env` 若仍是默认值，deploy.sh 会告警）。改后 `docker compose up -d` 重建。
3. **首登改 admin 密码**：平台对默认密码账号强制首登改密（`must_change_password`）。
4. **开登录 IP 白名单**（公网强烈建议）：系统管理→设置→登录安全，填办公出口 IP/CIDR
   （如 `203.0.113.0/24`）。开启后名单外 IP 无法登录，是暴力破解的终极闸。
5. **确认 S3 端口未暴露**：rustfs 9000/9001 在 compose 已绑 127.0.0.1（旧版本曾裸暴露，
   升级后执行 `docker compose up -d` 使生效）。
6. **配告警通道**：系统管理→通知通道 配企微/邮件——锁定告警、任务失败等才有出口。

## 5. 建议项（风险再降一级）

| 项 | 做法 |
|---|---|
| SSH 加固 | `/etc/ssh/sshd_config`：`PermitRootLogin no`、`PasswordAuthentication no`（仅密钥）；装 `fail2ban` 自动封禁爆破 IP |
| 正式 TLS 证书 | 自签证书替换为域名证书（Let's Encrypt / 商业），放 `deploy/tls/vervedeck.{crt,key}` 后重建 web |
| 关 API 文档 | `.env` 设 `API_DOCS_ENABLED=false`（公网不暴露 /docs、/openapi.json 接口清单） |
| 收紧 CORS | `.env` 设 `CORS_ORIGINS=https://<你的域名>`（默认 `*`，同源部署下影响有限） |
| 关 Grafana 匿名 | `.env` 设 `GRAFANA_ANONYMOUS=false`（监控大屏 iframe 将要求 Grafana 登录；默认匿名只读 Viewer 便于大屏嵌入） |
| 审计留存 | `audit_logs` 表定期归档（按 ts），安全事件筛选条件 `action=security` |

## 6. 已知边界（诚实声明）

- 登录失败计数存于 **backend 进程内存**：backend 重启会清零（攻击者进度丢失，对我们有利）；
  多副本部署不共享计数（当前形态为单实例，无此问题）。
- `X-Forwarded-For` 可被客户端伪造，**仅当 backend 只接受来自受信反代（nginx）的请求时可信**——
  本部署 backend 不监听公网，拓扑保证成立。
- Grafana 默认匿名只读 Viewer：指标数据（GPU/节点/任务量级）对公网可见，介意则按上表关闭。
- 护栏/内容安全是业务层能力，不属于本文范围。
