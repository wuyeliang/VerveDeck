## 5. 已知限制与后续建议

1. **单卡约束**：开发验证机为单 GPU，`replicas × tensor_parallel ≤ 1`。生产 8×4090 可放大副本/TP；scale 端点已做 GPU 余量校验（超限返回 400）。
2. **登录锁存内存**：失败计数存 backend 进程内存，backend 重启即清零（符合单实例部署；多副本需迁 Redis）。
3. **测试镜像不含 tests**：backend 镜像为精简运行镜像，测试文件需 `docker cp` 注入（见 `06-测试体系.md`）。
4. **deprecation 警告清理**：parametrize-generator / Pydantic class-config / 短 JWT key 警告可后续统一清理，不影响功能。
5. **可视化细节**：参照改造类需求的像素级视觉对齐可在补发参照截图后微调。
6. **小模型合成质量**：合成数据功能对 ≤1B base 模型只能保证「格式可用」（实测 0.5B 单次可解析率 80%、重试后 ~99%），产出质量有限，生产建议用 ≥7B 或 Instruct 模型合成。
7. **代码入库**：主体交付已入库（`9e12486`）；本轮全新部署修复（opensearch chown / 测试动态发现 / 合成鲁棒性）随 v1.1 一并提交。
