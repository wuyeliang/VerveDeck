# 运维手册

## 1. 目录与入口

| 项 | 位置 |
|---|---|
| 源码树 | `/opt/vervedeck/`（deploy/ images/ platform/ docs/） |
| 数据根 | `/data/`（模型/数据集/任务/上传/GPU 心跳/各服务数据） |
| 对象存储卷 | 命名卷 `fintune_rustfs-data`（`docker volume inspect`） |
| Web 控制台 | `https://<ip>`（443 强制 HTTPS，自签证书） |
| rustfs 控制台 | `http://<ip>:9001`（默认 rustfsadmin/rustfsadmin） |
| 推理 API 基址 | `https://<ip>/v1/<deploy_name>`（OpenAI 兼容，经 web/backend 反代，项目 API Key 鉴权） |

## 2. 日常命令

```bash
cd /opt/vervedeck/deploy

# 状态与日志
docker compose ps
docker compose logs -f --tail=100 backend      # 后端（含调度器 5s tick 日志）
docker compose logs -f mineru                  # PDF 解析服务
docker compose logs fintune-rustfs-1           # 对象存储

# 重启/升级
docker compose restart backend                 # 重启后端
docker compose build backend && docker compose up -d backend   # 改后端代码后
docker compose build web     && docker compose up -d web       # 改前端代码后
REBUILD=1 bash build-images.sh                 # 重建任务镜像（如升级 LLaMA-Factory/vLLM）
docker compose pull rustfs && docker compose up -d rustfs      # 升级 rustfs
```

## 3. 故障排查

### 3.1 backend 不健康 / API 500

```bash
docker compose logs backend | tail -50
docker compose exec backend curl -sf http://127.0.0.1:3001/health
docker compose exec backend python -c "from app.services import storage; print(storage.health())"
# 依赖检查
docker compose exec backend python -c "import psycopg2; print('pg ok')"
docker compose ps postgres rustfs opensearch   # 依赖是否 healthy
```

### 3.2 GPU 任务卡 queued

- `GET /api/cluster/queue` 看占用：常驻推理部署占着 GPU → 停掉或用空闲卡；
- 调度器要求节点 `online` 且 `gpu_count>0`：`GET /api/cluster/nodes`；
- gpu-agent 容器是否正常写心跳：`tail /data/gpu/agent.csv`、`cat /data/gpu/agent.ts`；
- 任务镜像缺失：`docker images | grep fintune`，缺则 `bash build-images.sh`。

### 3.3 对象存储异常

```bash
# rustfs 进程/日志
docker compose logs rustfs | tail -30
curl -s http://127.0.0.1:9000/health
# 桶与对象（backend 容器内）
docker compose exec backend python -c "
from app.services import storage
c = storage.client()
print([o.object_name for o in c.list_objects('vervedeck-datasets', recursive=True)][:20])"
# 重建桶（数据会丢，谨慎）
docker compose exec backend python -c "
from app.services import storage
c=storage.client(); c.make_bucket('vervedeck-datasets', exist_ok=True); print('ok')"
```

S3 不可用时平台**不中断**：数据集写入只留本地缓存（日志有 `s3 upload ... failed` 告警），
恢复后新写入自动同步；历史版本可手动补传（`storage.put_dir`）。

### 3.4 训练任务失败

```bash
# 失败原因（DB 存最后 30 行日志）
docker compose exec backend python -c "
from app.database import SessionLocal
from app.models import TrainingJob
db=SessionLocal()
for j in db.query(TrainingJob).filter(TrainingJob.status=='failed').order_by(TrainingJob.id.desc()).limit(3):
    print(j.id, j.name, (j.error or '')[:300])"
# 完整日志
cat /data/jobs/<id>/run.log | tail -80
# 配置复核
cat /data/jobs/<id>/config.yaml
# checkpoint 还在 → 页面点"断点续训"
ls /data/jobs/<id>/ckpt/
```

常见失败：OOM（降 batch / 开 zero3 / 开 gradient_checkpointing / 降 cutoff_len）；
参数非法（看 run.log 首行 HF parser 报错，核对 [04-训练参数全表.md](04-训练参数全表.md)）；
磁盘满（`df -h /data`，清理旧 jobs ckpt：`save_total_limit` 之外手动删）。

### 3.5 backend 重启后的 running 任务

调度器 5s 内会把丢失 exec 上下文的任务标记 `failed`（提示断点续训），checkpoint 保留在
`/data/jobs/<id>/ckpt/`，页面点"断点续训"即可续上。

## 4. 备份与迁移

**必须备份**（其余可重建）：
1. `/data/postgres`（或直接 `pg_dump`）—— 全部业务元数据；
2. rustfs 卷 `fintune_rustfs-data`（数据集版本主存储）——或 `mc mirror` 桶到远端；
3. `/data/datasets`（本地缓存，可选；丢 S3 主存储后无）；
4. `/data/models/hub`（基座权重；可重新下载，建议保留省流量）；
5. `deploy/.env`（密钥）。

```bash
# pg_dump
docker compose exec postgres pg_dump -U fintune fintune > backup_$(date +%F).sql
# rustfs 桶
docker run --rm -v fintune_rustfs-data:/data rustfs/rustfs:latest rustfs ...  # 或 mc mirror
# 迁移新机：按 02-一键部署.md 部署后，停栈 → 覆盖 /data 与命名卷 → 起栈
```

## 5. 容量与清理

| 项 | 建议 |
|---|---|
| `/data/jobs/<id>/ckpt` | 每任务 save_total_limit 份 checkpoint；旧任务手动清理（保留 merged 产物路径） |
| `/data/gpu`（指标） | 调度器每小时 GC 6h 前 GpuMetric，无需干预 |
| DVC 历史 | `.git` 增长后用 `dvc gc`（各数据集仓内） |
| rustfs 桶 | `mc du` 评估；删除数据集已自动清 S3 前缀 |
| HF 缓存 | `/data/hf-cache` 可定期清（模型已落 hub 目录） |

## 6. 安全基线（生产）

- 改 `JWT_SECRET` / `ADMIN_PASSWORD` / `POSTGRES_PASSWORD` / rustfs 凭据（`deploy/.env` 后 `up -d` 重建）；
- 9000/9001 端口勿暴露公网（防火墙）；S3 凭据最小权限；
- API Key 走项目级（`/api/admin/projects/{pid}/api-keys`），泄露即删；
- 审计日志保留策略：`AuditLog` 表按 `created_at` 归档（平台未内置清理，DBA 计划任务）。
