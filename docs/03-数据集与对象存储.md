# 数据集与对象存储

## 1. 数据模型

- **Dataset**：项目内命名数据集（`/data/datasets/p{project_id}/{name}/`），独立 Git+DVC 仓；
- **DatasetVersion**：不可变版本（`v1, v2, …`），每次清洗/合成/解析/上传产生新版本：
  - `data.jsonl`：规范化样本（alpaca / dpo 格式）
  - `raw.md`：（文档解析时）原始 markdown
  - `fmt`：`alpaca`（instruction/input/output）或 `dpo`（prompt/chosen/rejected）
- **DVC**：本地元数据版本控制（remote 为 `/data/dvc-remote`），`dvc-log` 可查提交历史；
- **对象存储（rustfs）**：版本文件的**主存储**，见下节。

## 2. 对象存储架构（rustfs / S3）

```
                commit 版本
  上传/解析/清洗/合成 ─────────────►  本地 /data/datasets/.../v{n}/data.jsonl   （处理缓存）
                                          │
                                          │ storage.put_dir（同步上传）
                                          ▼
                          rustfs 桶 vervedeck-datasets
                          key = 本地路径相对 /data
                          例: datasets/p16/客服问答/v1/data.jsonl
                                          ▲
  训练/评测/清洗/合成 读数据 ──► ensure_version_local ──► 本地命中？─是─► 直接用
                                            │否
                                            ▼
                                 storage.ensure_local 回源下载
```

**约定**：
| 操作 | 行为 |
|---|---|
| 写（版本 commit） | 先落本地缓存，再 `put_dir` 全量上传 S3；上传失败仅告警（本地仍完整） |
| 读（所有消费点） | 统一走 `ensure_version_local` / `ensure_version_raw`：本地命中直接用，未命中从 S3 回源 |
| 删（删除数据集） | 删本地目录 + DVC 元数据 + S3 前缀（`storage.delete_dir`） |
| 降级 | `S3_ENDPOINT` 为空 → 全部调用点自动降级纯本地，功能无差异 |

**读路径接入点**（全部已切换为 `ensure_version_local`）：
- 训练：`training_service.build_config`（数据 symlink 前保证本地存在）
- 评测：`eval_service.build_test_file`（转 test.jsonl）
- 数据预览 / raw 文件 API
- 清洗 worker、合成 worker（backend 进程内线程）

**S3 key 布局**（与本地一一对应）：
```
vervedeck-datasets/
└── datasets/p{project_id}/{name}/v{n}/
    ├── data.jsonl
    └── raw.md            # 仅文档解析产生
```

## 3. 数据生产管线

| 入口 | 说明 | 执行方式 |
|---|---|---|
| 上传 JSONL/JSON/CSV | `POST /api/datasets/{id}/versions/upload` | 即时，生成 v{n} |
| 文档解析（MinerU） | PDF/Word/PPT/图片 → markdown → SFT 样例（可选） | 常驻 mineru 服务（1 GPU） |
| 清洗 | 去重/长度过滤/JSON 修复/脱敏/护栏检测 | backend 线程 |
| 合成 | 用项目内推理部署生成 QA / CoT 数据 | backend 线程调 OpenAI 兼容端点 |
| 标注 | 推送 Argilla → 人工标注 → 回收为新版本 | Argilla 2.x + OpenSearch |

所有产出都生成**新版本**（不可变），训练任务永远引用版本 id，可复现。

## 4. 护栏（GuardRule）

- 正则规则，scope：`input`/`output`/`both`，支持项目级与全局（`project_id=None`）；
- 数据集创建/上传时检测输入样本；推理 API 代理层检测输出；
- 命中即 400 拒绝并写审计日志；非法正则跳过不崩。

## 5. 模型仓库与血缘

- 基座模型：`POST /api/models/base`（hf_id）→ 调度器线程 `snapshot_download`（HF 镜像）→ ready；
- 训练成功自动注册 **LoRA 产物**（`type=lora`，记录 parent/基座、job_id、dataset_version_ids）；
- export 合并产物 `type=merged`；`GET /api/models/{id}/lineage` 查血缘链。

## 6. 容量与清理建议

- S3 桶与本地缓存双份占用磁盘；本地缓存可在确认训练/评测不用旧版本后清理
  （删除本地文件不影响 S3 主存储，下次读取自动回源）；
- 建议定期用 `mc du vervedeck/vervedeck-datasets` 评估桶容量；
- DVC 历史（`.git`）随版本增长，长期可 `dvc gc` 清理无引用对象。
